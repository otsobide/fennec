# MISP attribute types: catalogue, validation, correlation and storage model

Research notes for the Fennec observable/IOC data model. All paths are relative to the MISP clone root (`.misp/`) unless prefixed otherwise (`.misp-objects/`, `.stix2-json-schemas/`, `.opencti/`). Line numbers refer to the clone state below.

Conventions in this document:

- **[SRC]** marks a statement of fact taken from source code, with file and line references.
- **[REC]** marks my own recommendation or interpretation for Fennec. Everything in the "STIX/OpenCTI hint" and "class" columns of the catalogue is [REC].
- **[INF]** marks behaviour inferred from PHP language semantics that I could not execute (no PHP interpreter on this machine); regexes were re-checked with Python `re`, which has identical semantics for the patterns involved.

## 1. Key findings (summary)

1. 194 attribute types, 16 categories, 25 composite types (24 whose name contains `|` plus the hard-coded `malware-sample`, `app/Model/MispAttribute.php` L1039-1055). 96 types default to `to_ids=1`, 98 to `to_ids=0`.
2. Validation is weak for half of the types: 59 types are only checked for "no newline", 35 types accept anything (`return true`) and 1 type has no rule at all (it throws). The other 99 types have a syntactic check (hash lengths, IP, domain regex, email regex, port range, etc.), several of them very loose (`is_numeric`, `^.+$`). No checksum validation exists for any financial identifier (IBAN, BTC, credit card).
3. Type-specific normalisation exists for 76 types in `modifyBeforeValidation` (lowercase for hex hashes, punycode for `domain`, IPv6 compression, phone/IBAN cleanup, AS dot notation, MAC formatting), plus refanging for 10 types. It is inconsistent: `hostname` is lowercased but not trimmed or punycoded like `domain`; `eppn`, `jabber-id`, `dns-soa-email` are email-validated but not lowercased; `git-commit-id` is hex-validated but not lowercased; `ssh-fingerprint` and extension ids are not normalised.
4. A global pre-step replaces every 4-byte UTF-8 character with `?` for every type (`AttributeValidationTool.php` L69, L790-807, "Temporary solution for utf8 columns until we migrate to utf8mb4"). This is lossy and exists because `attributes.value1/value2` are `utf8mb3` columns (`INSTALL/MYSQL.sql` L76-78).
5. Source bugs: `filename|impfuzzy` has no `validate()` case, so saving one throws `InvalidArgumentException("Unknown attribute type ...")` (L647); `integer` rejects `"0"` because `filter_var("0", FILTER_VALIDATE_INT)` returns `0`, which is falsy (L607-613) [INF]; `boolean` coerces any truthy string (for example `"no"`) to `1` (L224-231); the domain regex accepts IPv4-looking strings whose last octet has 2+ digits (for example `10.0.0.10`) and multiple consecutive dots.
6. Correlation is exact string equality on `value1`/`value2`, **type-agnostic** (a `text` attribute correlates with an `ip-dst` of the same value), excluding 12 non-correlating types and the port half of 3 `x|port` composites. Optional advanced correlation: CIDR containment for 4 IP types and ssdeep fuzzy matching.
7. Storage is a single EAV-like `attributes` table for all 194 types with `type varchar(100)`, `value1 text`, `value2 text` and prefix indexes `value1(255)`/`value2(255)`; correlations are materialised as a pairwise table (`default_correlations`) with 20 denormalised ACL columns per pair. This is quadratic in the number of occurrences of a value and MISP caps it with `correlation_limit` (default 20) and `max_correlations_per_event` (default 5000), silently dropping correlations beyond the caps.
8. [REC] For Fennec: 11 types are pure generic catch-alls and 14 more are free-form containers; 13 are detection rules (not observables); 8 are references to threat-intel objects (SDOs, not observables); 25 are PII. Many types are role variants of the same observable kind (ip-src/ip-dst, email-src/email-dst/target-email/whois-registrant-email/dns-soa-email) and should collapse into one aggregate with the role carried by a relationship.

## 4. Composite types (value1 / value2)

[SRC]

- `getCompositeTypes()` (L1039-1055): `['malware-sample']` (comment: `// TODO hardcoded composite`) plus every type whose name contains `|`. Result: 25 types.
- Validation requires exactly one `|` in the whole value (`validComposite`, L930-938: `substr_count($fields['value'], '|') !== 1`), so a file name, registry value data or anything else containing `|` cannot be stored in a composite type.
- `beforeSave` splits on `|` (L566-579); `value2` is `''` for non-composite types.
- `malware-sample` value is built as `$filename . '|' . $result['md5']` (L3018); the encrypted zip is stored on disk via AttachmentTool (`ZIPPED_DEFINITION`, L119).
- Correlation for `PRIMARY_ONLY_CORRELATING_TYPES` (`ip-src|port`, `ip-dst|port`, `hostname|port`, L326-330) uses only `value1`; the port never correlates.
- `checkComposites()` (L1251-1263) is an admin integrity check that loads **all** attributes (`find('all')`) to find composites with an empty half.

## 7. Correlation: which types correlate

[SRC]

- `NON_CORRELATING_TYPES` (`app/Model/MispAttribute.php` L311-324): `comment`, `http-method`, `aba-rtn`, `gender`, `counter`, `integer`, `float`, `port`, `nationality`, `cortex`, `boolean`, `anonymised` (12 types). Note the stray comment `// skip Correlation for the following types` sits above `IMAGE_EXTENSIONS` (L307-309), not above this constant.
- `PRIMARY_ONLY_CORRELATING_TYPES` (L326-330): `ip-src|port`, `ip-dst|port`, `hostname|port`: only `value1` correlates.
- The remaining 182 types correlate on `value1`; composite ones (except the 3 primary-only types) also correlate on `value2`.
- Matching is exact equality, type-agnostic: `afterSaveCorrelation` builds `Attribute.value1 = $cV` OR (`Attribute.value2 = $cV` AND type not primary-only), restricted only by `Attribute.type NOT IN NON_CORRELATING_TYPES`, other event, `disable_correlation = 0` on attribute and event, not deleted (`app/Model/Correlation.php` L520-570). There is no type filter, so `text` = `8.8.8.8` correlates with `ip-dst` = `8.8.8.8`, and every `filename` half of `filename|hash` correlates with every equal `filename`.
- [SRC] In MySQL the comparison follows the column collation `utf8mb3_unicode_ci` (case-insensitive, `INSTALL/MYSQL.sql` L77-78); in PostgreSQL `text` equality is case-sensitive (`INSTALL/POSTGRESQL.sql` L79-80). [INF] Correlation results therefore differ between backends for values that differ only by case (for example BTC bech32 addresses, URLs, registry keys).

Exclusion mechanisms [SRC]:

| mechanism | effect | where |
|---|---|---|
| `attributes.disable_correlation` | per attribute | `Correlation.php` L473, L530 |
| `events.disable_correlation` | per event | L489, L531 |
| `MISP.completely_disable_correlation` | global off; enabling triggers full recorrelation, "an extremely long and costly procedure" | L473; `app/Model/Server.php` L6995-7003 |
| image attachments | `disable_correlation=true` set automatically | `MispAttribute.php` L921-925 |
| `correlation_exclusions` table (cached in Redis set `misp:correlation_exclusions`) | value exact, or `%x`, `x%`, `%x%` patterns | `Correlation.php` L624-663 |
| `over_correlating_values` | value blocked once matches exceed `correlation_limit` (default 20); value truncated to 191 chars and lowercased | `Correlation.php` L589-599; `OverCorrelatingValue.php` L11-18, L46-61, L84-87; `Server.php` L5955-5962 |
| `correlation_rules` | custom conditions per selector | `Correlation.php` L540; `INSTALL/MYSQL.sql` L285-298 |

Advanced correlation (off by default, `enable_advanced_correlations`, "Enable some performance heavy correlations (currently CIDR correlation)", `Server.php` L5971-5978):

- CIDR: for `ip-src`, `ip-dst`, `ip-src|port`, `ip-dst|port` (`Correlation.php` L304-305, L702-790). A CIDR attribute scans all non-CIDR IPs of those types (MySQL fast path with `INET_ATON(value1) BETWEEN ? AND ?` and `value1 LIKE prefix%`, L717-744; other backends fetch every IP and test in PHP). A plain IP is tested against the full CIDR list kept in Redis `misp:cidr_cache_list` (L1062-1105).
- ssdeep: chunked n-gram index `fuzzy_correlate_ssdeep(chunk varchar(12), attribute_id)` then `ssdeep_fuzzy_compare` >= `MISP.ssdeep_correlation_threshold` (default 40) (`Correlation.php` L669-696; `app/Model/FuzzyCorrelateSsdeep.php` L58-80; `Server.php` L6030-6036).

Correlation engines [SRC] (`Correlation.php` L38-43; `Server.php` L5942-5954): `Default` (`default_correlations`, ACL columns), `NoAcl` (`no_acl_correlations`, "much leaner and faster" for endpoint instances), `OnDemand` (no table, computed at read time, "MySQL/MariaDB only"), `Legacy` (`correlations`, still in `$validEngines` but not offered in settings options).

| 1 | **One untyped table for 194 types.** `value1`/`value2` are `text`; types and categories are strings. ## 13. Recommendations for Fennec [REC]

1. **One aggregate per observable kind, not per MISP type.** Collapse role variants (section 9) and carry the role on the relationship (STIX `network-traffic.src_ref/dst_ref`, `email-message.from_ref/to_refs`, OpenCTI `targets`, `resolves-to`). By the table in section 9, about 80 MISP types collapse into 9 kinds without losing information.
2. **Decompose composites at the import boundary.** `filename|sha256` becomes one `File` aggregate with `name` and `hashes[SHA-256]`; `domain|ip` becomes `DomainName` + `IPv4Address` + `resolves-to` relationship; `ip-dst|port` becomes `NetworkTraffic{dst_ref, dst_port}`; `regkey|value` becomes `WindowsRegistryKey{key, values[]}`. Never store `|`-joined values.
3. **Value objects own validation and canonicalisation.** Each VO constructor validates strictly (fix MISP gaps: label/total length for domains, real URL parsing, MAC-48 vs EUI-64, checksums for IBAN mod-97, Luhn for card numbers, base58check/bech32 for BTC, CPE 2.3 grammar, ISO 3166 for countries) and produces the canonical form used as the dedup key (lowercase hex hashes, punycode lowercase domains, compressed IPv6, E.164 phone numbers, UTC timestamps). Keep the raw input as a separate field when canonicalisation is lossy.
4. **Lenient import, strict domain.** MISP data will contain values that fail strict rules (MISP accepted them). The MISP import adapter needs a quarantine/rejection report rather than silently coercing, and must trust the declared MISP type (hash lengths are ambiguous, section 5.1).
5. **No generic types in the domain.** The 11 catch-alls (`text`, `comment`, `other`, `hex`, `anonymised`, `float`, `integer`, `counter`, `boolean`, `datetime`, `uuid`) must map to a typed property of a parent aggregate (they are object components in MISP: `text` in 437 templates, `datetime` in 217), to a Note, or be rejected. `text` should not become an OpenCTI-style `Text` observable in Fennec's core model.
6. **Detection rules (g) are not observables.** Model them as an `Indicator` aggregate with a closed `PatternType` enum (stix, yara, sigma, snort, suricata, zeek, kql, gene, plus "pattern-in-*" as custom) and validate syntax per type where parsers exist.
7. **Threat-intel references (i) are SDO links.** `threat-actor`, `campaign-*`, `vulnerability`, `weakness`, `target-org`, `target-location`, `target-external` should resolve to (or create) SDO aggregates and relationships, never be stored as observables.
8. **PII (f) in its own bounded context** with stricter access control and no automatic correlation; MISP already excludes `gender` and `nationality` from correlation.
9. **PostgreSQL design.** Global observable identity (unique on `(kind, canonical_value)` or a deterministic STIX id), native types (`inet`/`cidr` with a GiST `inet_ops` index for containment, `bytea` or fixed-length hex for hashes, `int4`/`int8` for ports and ASNs, `timestamptz`), `utf8` everywhere (PostgreSQL `UTF8` has no 3-byte limitation), and a `report_observable` (container-to-observable) association table. Correlation then becomes "observables shared by containers" via an index join, with no pairwise materialisation and no per-value caps needed.
10. **Correlation semantics should be type-aware** (same kind and canonical value), with CIDR containment and fuzzy hash similarity as explicit, separately indexed relations rather than ad hoc queries.

## 14. Open questions

1. Hostname vs DomainName: OpenCTI has a separate custom `Hostname` observable and MISP has both `hostname` and `domain` with different normalisation. Does Fennec keep two kinds (OpenCTI parity) or one kind with a flag?
2. Email address roles: is `email-reply-to` (not email-validated in MISP) imported as `EmailAddress` (strict) or as an email-message header property?
3. JA3, JARM, HASSH, favicon-mmh3, dom-hash, community-id, cookie and DKIM have no STIX 2.1 SCO; does Fennec define custom kinds (with `x-` STIX extensions) or properties of NetworkTraffic/X509Certificate/Url?
4. How should Fennec treat MISP values that fail Fennec's stricter rules (for example `integer` "0" accepted elsewhere, IP-looking domains, truncated 4-byte characters already replaced by `?`)?
5. The misp-stix converter submodule is empty in this clone; the authoritative MISP to STIX 2.1 mapping (`misp_stix_converter`) should be checked to align the hints in the catalogue.
6. PII types (25) and `pgp-private-key`: are they in scope for the observable model or confined to a separate, access-restricted context?
